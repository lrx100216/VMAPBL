## 1. 当前可用条件与演示边界

已验证：双击启动器、真实 dashboard、规则启停、药品持久化、消息链路、通知 outbox、健康检查。相关 21 项 demo 测试通过，项目全量测试此前为 353 项通过。

当前环境：

- `/Applications/VMAPBL Butler.app` 已安装，视频源为 **RTSP 网络流**，语音回路已启用。
- DeepSeek Key 已配置，但演示前仍需实测网络与模型可用性。
- 已标定 `bed`、`door_inside`；`door_outside` 未标定，**不做完整出门/回家方向演示**。
- 药盒模型不存在，吃药只能演示“提醒 + 语音确认降级”，不能声称视觉服药识别。
- 钉钉、飞书、独立看门狗和 HA 地址未配置，**不演示外部真实送达**。
- 只有 `tests/media/smoke_none_01.mp4`，没有足够实景正负样本，**不展示准确率数字**。
- 视频通话、方言录制、拍照添加药品仍未接入，页面保持禁用，不作为 demo 功能。

主模式建议：`classic`，保证本地感知和安全兜底可展示；VLA 作为可选追加，不作为 demo 成功的单点依赖。

## 3. 准备阶段（预计 30–45 分钟）

### 3.1 保留现有数据，不重建环境

- 不重装 `.venv`，不删除数据库，不覆盖现有 ROI。
- 演示会产生真实事件和消息，提前告知观众这是 demo 数据，不清理既有记录。
- 若需要干净环境，先备份整个项目目录和 `data/`，不要直接删除原文件。

### 3.2 运行基础自检

```bash
cd /Users/liuruixuan/VMAPBL
DEEPSEEK_API_KEY= DEEPSEEK_BASE_URL=http://127.0.0.1:9 .venv/bin/python -m pytest -q
.venv/bin/python main.py --list
.venv/bin/python tools/permission_check.py
```

检查：摄像头可读、麦克风非静音、API/模型可用。API 自检会发起一次真实模型请求；网络或额度不可用时，按第 6 节降级，不反复重试。

### 3.3 启动与页面检查

1. 在“应用程序”中双击 **VMAPBL Butler.app**。
2. 等自动打开 `http://127.0.0.1:8321/`。
3. 再双击一次，确认只打开页面，不启动第二个服务。
4. 首页应显示“实时数据”，不是“演示数据”。
5. 打开 `/debug`，确认真实画面和 ROI 工具仅用于调试，不放在主展示页。

如果启动失败，看 `logs/launcher.out.log` 与 `logs/butler.log`，不要反复双击。

### 3.4 准备三样道具

- 一张大字体说明纸：“每日三次，每次一片”。
- 一个普通药盒，仅用于 OCR/说明，不宣称已经视觉确认服药。
- 一位现场配合者扮演老人，安全地说“我没事”，不做真实跌倒动作。

## 4. 分钟级操作脚本

### 0:00–0:45 双击启动

话术：“这套系统不需要老人打开 App。双击以后，感知、语音和家人控制台一起启动。再次双击不会重复占用摄像头。”

检查：控制台可访问，服务未重复启动。

### 0:45–2:00 老人主动联系家人

对麦克风清楚说：

> 给儿子发消息说我晚上过去吃饭。

预期：语音识别 → 意图 `message` → 消息进入家人控制台与事件时间线。

备用操作（麦克风或 STT 失败）：

```bash
curl -sS -X POST http://127.0.0.1:8321/api/msg_to_elder \
  -H 'Content-Type: application/json' \
  -d '{"text":"妈，晚上我过去吃饭"}'
```

这个备用请求验证的是“家人 → 老人”链路，不要把它说成语意识别成功。

### 2:00–3:00 家人问状态

在控制台手动触发 `family_query`，或执行：

```bash
curl -sS -X POST http://127.0.0.1:8321/api/trigger/family_query \
  -H 'Content-Type: application/json' -d '{"text":"我妈在干嘛"}'
```

预期：返回一句可观测描述或“无法确定”。如果模型不可用/画面不清，接受明确的不确定结果，不能现场编一个状态。

### 3:00–4:00 拍照读字

把说明纸放到镜头前，说：

> 帮我念一下上面写的什么。

预期：本地 OCR 朗读；语义问题才升级 VLM。若失败，换成“这药一天吃几次”演示语义问答；仍失败就明确说明当前画面/模型限制，转下一段。

### 4:00–5:00 跌倒二次确认（安全演示）

```bash
curl -sS -X POST http://127.0.0.1:8321/api/trigger/fall \
  -H 'Content-Type: application/json' -d '{}'
```

系统询问“您还好吗”时，现场回答：“我没事。”

预期：撤警，不给家人发紧急通知。只展示确认逻辑，不表演真实跌倒，也不宣称模型已经识别了真实跌倒。

### 5:00–6:00 规则与药品真实持久化

1. 在“智能提醒”停用再启用一个规则，说明这是 PATCH 到后端，不是浏览器假开关。
2. 打开药品管理，添加“演示药”：余量 12 片、提前 3 天。
3. 刷新页面，确认规则和药品仍在。

接口核验：

```bash
curl -sS http://127.0.0.1:8321/api/rules
curl -sS http://127.0.0.1:8321/api/drugs
```

### 6:00–7:00 健康与降级

```bash
curl -sS http://127.0.0.1:8321/healthz
curl -sS http://127.0.0.1:8321/readyz
```

说明：`healthz` 只代表进程活着；`readyz` 还检查新鲜画面、姿态模型、数据库和通知队列。当前通知未配置时，展示 pending/dead 是诚实降级，不是“全部完美”。

### 7:00–8:00 总结

强调：主页无实时画面，只有结论；没有外部通知时不假称家人已收到；没有真实样本时不报准确率。

## 6. 故障备用方案

| 故障 | 备用演示 | 不得声称 |
|---|---|---|
| RTSP/摄像头失败 | 用 `/debug` 排障，展示 `/readyz` 降级；继续 API、规则和药品演示 | 视觉识别成功 |
| 麦克风/STT失败 | 用留言 API 验证家人链路 | 语音识别成功 |
| DeepSeek/网络失败 | 展示本地 OCR、几何/语音兜底和 `uncertain` 结果 | 云端 VLM 已返回真实状态 |
| 无钉钉/飞书 | 展示控制台消息、outbox pending/dead 与 `/readyz` | 家人已收到通知 |
| 只有 mock 页面可用 | 用 `/?demo=1` 展示布局，并明确说是设计演示 | 实时生产数据 |
| 时间不足/素材不足 | 做 5 分钟核心链路，不报准确率 | 已完成实景验收 |

## 8. Demo 与生产验收的区别

本 demo 只证明主要交互和降级路径可用，不等于完成：HA 接入、真实外部通知、RTSP 长时间稳定、72 小时连续运行、故障注入和实景准确率验收。生产放行仍需按 `docs/production-hardening-plan-2026-11-02.md` 的 P3/P4 执行。
