## 2. 总体实施顺序

| 阶段 | 目标 | 粗估（1 名开发者） | 放行条件 |
|---|---|---:|---|
| P0 安全止血 | 模型输出沙箱、语音生命周期、误服药、依赖与生产前置 | 2–3 天 | 新增对抗测试全绿，无已知静默卡死路径 |
| P1 可值守可靠性 | 健康降级、状态持久化、可靠通知、启动与视频 freshness | 3–4 天 | 重启/断网/模型失败均有明确降级与审计 |
| P2 真实数据闭环 | 仪表盘、规则、药品、快捷操作接真实数据 | 3–4 天 | live 模式无 mock 结论，所有展示能追溯来源 |
| P3 性能与工程收敛 | 资源指标、调度、配置、CI、文档与模块去重 | 3–4 天 | 可复现部署、指标可信、回归门禁生效 |
| P4 实景验收 | 正负样本、故障演练、72h 稳压与真机运维 | 3–5 天 + 72h | 形成 go/no-go 报告，不以“进程活着”代替验收 |

> 时间是实现与自动化验证的粗估，不包含硬件采购、平台审核和实景素材采集等待。

## P0：安全止血（最先做）

### P0-1 VLA 动作沙箱与决策异常兜底

**改动**：`core/vla_agent.py`、`core/state.py`、`tests/test_vla_agent.py`、`tests/test_audit_hardening.py`

- `UPDATE_STATE` 改为显式字段+类型白名单；禁止模型写 `speaking`、`last_trigger`，`occupancy` 默认也不允许云写。
- 数值解析统一 `_num(value, default, min, max)`；限制播报/通知文本长度、监听时长、等待时长。
- `decide()` 与 `decide_and_act()` 任一解析/模型异常都进入本地安全兜底并落 `error`，不得静默吞掉本次事件。
- OCR、语音和画面文本按不可信数据处理；模型输出不能直接获得额外动作权限。

**验收**：`speaking/last_trigger` 写入被拒；`"thirty"` 不再穿透；“未送达不静默”仍成立；新增异常路径测试通过。

### P0-2 修正服药语义，杜绝“吃饭=吃药”

**改动**：`core/vla_agent.py`、`actions/medication.py`、对应测试

- 语音确认必须同时满足“提到药”与“确认已服”，并处理否定表达；餐次从当前时段/规则获取，不再硬编码 `morning`。
- classic 与 VLA 共用同一套关键词与时段判定，避免同一句语音两种结论。

**验收**：「我吃了饭了」「我还没吃药」不记已服；「我吃过降压药了」按正确餐次记账。

### P0-3 修复 TTS 生命周期与输入上限

**改动**：`skills/tts.py`、`server/app.py`、`core/vla_agent.py`、测试

- `speak()` 无论成功、异常、取消、尾静默中断都复位 `speaking` 并释放锁。
- `say` 增加超时与进程终止；服务端留言、回调、模型输出统一限制长度（默认 200 字）。
- 保留现有 argv 与 `--` 防命令注入方式。

**验收**：取消/超时后麦克风立即可用；超长输入 422，且不产生播报或落库副作用。

### P0-4 生产前置与依赖可复现

**改动**：`requirements.txt`、新增锁定配置、`.env.example`、`tools/permission_check.py`、部署文档

- OpenCV 限制 `<5`，补 `torchaudio==2.9.1` 与直接依赖 `httpx`，生成并验证锁文件。
- 增加 `--require-production` 预检：非回环监听必须有 token；生产要求通知渠道、回调签名、模型文件、可写 DB/日志、合理的密钥文件权限。
- 将 `.env` 权限调整为 `0600`（由用户在本机执行）；`deliverables/` 中敏感审计材料继续不入库，移动或脱敏后再决定是否公开。
- 错误文本与日志统一脱敏，RTSP 地址不得包含账号密码。

**验收**：干净环境可按锁文件重建；缺 token/通知/模型时预检明确失败，不打印“已就绪”。

## P1：可值守可靠性

### P1-1 消除“进程活着但已经瞎了”

**改动**：`sensors/pose.py`、`sensors/perception.py`、`main.py`、`core/health.py`、`server/app.py`

- 姿态预热失败进入显式 `degraded`；CoreML 加载失败回退 `.pt`，仍失败则 readyz 503 并通知家人。
- 检查 `server_task.done()/exception()`，绑定失败不得启动语音/心跳或打印成功地址。
- 视频帧超时：状态置“未知/降级”，`sensor.health.degraded` 告警，`/api/frame` 拒绝陈旧缓存。
- `bus.publish_nowait` 保留任务强引用，新增 `drain()` 供停服和测试使用。

**验收**：模型缺失、CoreML 损坏、端口占用、摄像头冻结四种场景均有 503/降级事件/家人提示，不出现假在线。

### P1-2 通知从“调用过”升级为“可追踪结果”

**改动**：`skills/notify.py`、`core/vla_agent.py`、`core/log.py`、看门狗

- 仅网络传输错误、429、5xx 重试；尊重有上限的 `Retry-After`；增加整体回执截止时间和取消语义。
- `delivered / undelivered / pending` 三态进入消息与事件模型；VLA 未送达不得返回 `status=ok`。
- 紧急通知采用有界持久化待重试记录，重启后可恢复；成功才允许静默，失败必须可由看门狗发现。

**验收**：断网、平台业务拒绝、进程重启均不会伪造送达；重复告警受控但不会因一次失败永久沉默。

### P1-3 持久化安全状态与配置一致性

**改动**：`core/state.py`、`core/log.py`、`actions/medication.py`、`actions/wakeup.py`、`actions/fall.py`、`core/config.py`

- 用小型 `state_kv` 表保存当日服药、起床 pending、报警静默、场景冷却与每日触发记录；启动时恢复并校验日期。
- 配置启动校验：阈值范围、跨字段约束、模型路径；提供配置 fingerprint。ROI 可热更，其他字段明确“需重启”或实现统一热更新。

**验收**：重启不重复发药/报警、不丢升级链；错误阈值在启动时一次列全并失败，不发生“改了配置但仍在用旧值”。

### P1-4 统一视频源与隐私输出

**改动**：`skills/vision.py`、`sensors/camera.py`、`actions/family_query.py`

- 所有抓帧统一走 Camera 抽象，RTSP 单场景触发不再走 AVFoundation。
- 家人状态回复除提示词约束外增加输出校验；不确定时使用保守模板，不把衣物、健康猜测或位置细节发给家人。

**验收**：RTSP 下单场景可抓帧；陈旧/无画面明确显示未知；隐私负样本输出被拦截。

## P2：真实数据闭环（VLA 主路径不变）

### P2-1 先接只读仪表盘，再接写操作

**改动**：新增轻量 dashboard read model（建议 `server/dashboard.py`）、`server/app.py`、`core/log.py`、`server/static/index.html`、页面测试

- 新增只读接口：`/api/dashboard/summary`、`/api/dashboard/timeline`，从真实 state、events、messages、health 派生，保留 token 鉴权。
- 明确 `data_mode=mock|live`；mock 用于设计预览，live 模式不得再显示“演示数据”或伪造成功提示。
- 快捷操作中，发语音与一键安抚复用真实留言链路；**视频通话、方言录制未接入前禁用并标注，不提示成功**。

### P2-2 展示只承诺系统真实具备的能力

- 状态：优先使用“在家活动 / 在家静止 / 外出 / 未知”，不能仅凭 `is_still` 推断睡眠。
- “状态良好”改为可审计的安全摘要，不推断情绪。
- 设备在线数只展示实际可测的摄像头、语音、DB、通知；音箱和门磁无真实健康数据时显示“未接入”。
- 时间线来自事件日志，详情引用事件类型、时间和脱敏后的结论，不伪造起床时间或活动时长。
- 首页继续遵守“无画面、只有结论”；实时画面仅留 `/debug`。

### P2-3 规则与药品管理使用同一事实源

**改动**：`scenes/*.yaml`、`config/settings.yaml`、`actions/medication.py`、新增受校验的规则/药品接口与测试

- UI 的触发条件必须读取实际规则：当前后端没有“开门传感器”“穿戴整齐识别”，也没有现成的 08:00/13:00/19:00 三顿触发，不得按 mock 文案当成真实能力。
- 若要三顿用药，先在场景/调度中实现，再展示 3 次；否则界面按实际配置显示 1 次。
- 规则编辑采用 schema 校验、版本确认和明确的热生效/重启语义；话术、AI 确认方式、升级步长写回后立即可审计。
- 药品先做名称/余量/补药阈值持久化；在每次剂量不明时，不因“已服药”自动扣减库存。

**验收**：live 页面每个数字和状态都能追溯到 API/DB/事件；修改规则后刷新仍一致；不支持的能力明确显示“未接入”。

## P3：性能、调度与工程收敛

### P3-1 资源指标和缓冲修正

- `sensors/camera.py`：按实际编码 stride 计算 ring 长度，验证 60 秒窗口与内存预算。
- `sensors/sentinel.py`/`main.py`：用进程 CPU、RSS、帧年龄、推理延迟替换“单帧检查 <1ms = 全系统 CPU <1%”的误导指标。
- `tools/cost_report.py`：成本按 token/模型价格计算，固定每次单价只作显式估算。
- 长任务（吃药 1 小时观察窗）改为后台任务/事件回灌；HTTP 手动触发返回任务 ID，避免占住连接与定时循环。

### P3-2 减少 classic/VLA 再次分叉

- 抽取共享的安全关键词、状态写权限、报警静默与通知结果语义；先加一致性测试，再移动代码。
- `core/vla_agent.py` 仅在行为稳定后按“观察/归一化/执行/兜底”拆分；`sensors/sentinel.py` 不做无关重写。
- 保持单进程、单摄像头、轻量事件总线，不引入分布式队列或大型插件框架。

### P3-3 自动化质量门禁

- 建立锁定的开发依赖与 CI：离线 pytest、禁网检查、依赖 CVE 扫描、格式/静态检查。
- 首次测量语句与分支覆盖率，不沿用 2026-10-24 的旧覆盖率；对本次 P0/P1 新分支要求全覆盖，项目阈值按实测基线设定。
- 增加浏览器交互测试：页签、时间线展开、规则编辑、升级步长、药品表单、401 输入、live/mock 标识、无实时画面。
- 补 `ARCHITECTURE.md`（双模能力与降级矩阵）、`CONFIG.md`、`RUNBOOK.md`、事件/API 说明，README 不再手抄易过时的测试数字。

## P4：真机与实景验收（上线门槛）

1. **场景数据集**：每个场景至少 20 组带真实标签的正/负样本；跌倒含遮挡、姿态丢失、坐下/捡物，吃药含只喝水/拿药盒未服，起身含翻身。
2. **端到端演练**：老人发消息、家人问状态、家人留言与回复、告警送达；验证延迟和平台真实回执，不用 mock 回执替代。
3. **故障注入**：断网、摄像头冻结、RTSP 断开重连、模型损坏、API 401/超时、SQLite 写失败、Mac 睡眠/重启。
4. **72 小时稳压**：classic 与 VLA 分别运行，记录 RSS/CPU/帧年龄/通知成功率；数据库执行定期清理与备份恢复。
5. **上线判定**：所有 P0/P1 用例通过、live UI 无 mock 结论、告警链路有真实回执、看门狗能发现主进程与感知失效；未达标项保持“不用于无人值守”的明确声明。

## 明确不做（避免扩大范围）

- 不重写 VLA/classic 为另一套框架，不迁移到 Home Assistant，不引入分布式消息队列。
- 不把“睡眠、情绪、穿戴整齐、设备在线”用推断或 mock 伪装成真实能力。
- 不在没有服务提供商与权限模型前实现视频通话，不在没有录音上传/存储/播放链路前声称方言已可用。
- 不在剂量未知时自动扣药，不在没有本地 VLM 需求确认前增加新的模型运行时。
