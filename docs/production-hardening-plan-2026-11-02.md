# 控制台生产化实施与验收计划

日期：2026-11-02
目标：从“页面和单元测试可用”推进到“可部署、可恢复、可观测、可验收”的养老守护控制台。

## 验收原则

- 不用 `pytest passed` 代替真实安全性；每个阶段必须有故障场景和退出标准。
- 页面只展示可追溯事实；未知、未接入、降级必须明确显示，禁止 mock 冒充实时。
- 紧急通知必须先持久化，再外发；平台回执、pending、dead 与看门狗语义一致。
- VLA 为主，classic 保留本地安全兜底；禁止云端/模型获得额外系统权限。
- 保持单进程、单摄像头、轻量事件模型，不以分布式重构代替可靠性。

## P1 真实数据与配置闭环

### P1.1 只读仪表盘（当前阶段）

- 新增只读 dashboard summary/timeline API，来源限定为 `StateStore`、事件日志、消息、健康快照。
- 首页保留 `?demo=1` 展示 mock；正式默认 live，移除“演示数据”伪装。
- 状态只显示“在家活动/在家静止/外出/未知/降级”，不根据静止推断睡眠或情绪。
- 起床时间、活动时长、设备在线、用药次数均由真实事件推导；无法推导显示“未接入/未知”。
- 时间线按事件时间倒序，详情来自脱敏事件，不显示未经支持的画面或健康结论。

### P1.2 快捷操作与规则

- 发语音、一键安抚复用真实家人留言链路，返回任务/消息状态；失败不得 toast 成功。
- 视频通话、方言录制在提供实际服务前禁用并标注“未接入”。
- 规则列表从 `scenes/*.yaml` 和配置生成，不能显示不存在的门磁、穿戴识别或三顿调度。
- 规则编辑做 schema 校验、版本确认和审计；热更新/重启边界明确。
- 药品先做名称、余量、补药阈值持久化；剂量未知时不自动扣库存。

### P1.3 生产配置

- 配置访问 token、平台回调签名、家人通知和独立看门狗；保持 `.env=0600`。
- `--require-production` 必须通过才允许正式运行；缺配置时明确降级/拒绝，不假称生产就绪。

**退出标准**：live 首页每个字段可追溯；刷新后规则与药品仍一致；不支持的按钮不能提示成功；token 下 API/WS 全流程通过。

## P2 并发、资源与安全生命周期

- 哨兵慢决策与采样解耦，有界合并普通事件；高危事件不得被长回调饿死。
- 摄像头打开/重连不阻塞 event loop；处理 `stop()` 超时线程句柄和重启竞争。
- outbox 有界并发与公平调度，保留 Retry-After，避免慢消息阻塞整批。
- 服药观察窗改可取消后台任务，手动触发返回任务 ID；长任务不占用定时循环。
- ring buffer 按实际编码频率保留 60 秒；数据库各表有保留/备份策略。
- launchd stdout/stderr 轮转；避免敏感原文进入未轮转日志。
- WebSocket 所有 pending task 在异常/取消时统一清理；TTS/STT 锁避免跨 loop 绑定。

**退出标准**：断网、摄像头冻结、慢 webhook、连续 100 条到期通知下，高危事件仍有界响应；无孤儿任务、无线程竞争、无无限增长日志/DB。

## P3 真机接入与部署

- 接入实际 RTSP 摄像头、麦克风/音箱、钉钉主通知；HA 按计划接入（当前仍缺 HA 地址）。
- 配置 launchd guardian/watchdog、caffeinate、日志轮转、独立告警通道。
- 生产预检覆盖模型、可写路径、通知、签名、token、HA/设备配置。
- 若使用 classic 几何场景，完成门内外/床区 ROI；VLA 不强制自训药盒模型。

**退出标准**：目标 Mac 冷启动可拉起，RTSP 断开自动恢复，主进程崩溃自动重启，看门狗独立告警可达。

## P4 实景与连续运行验收

1. 每场景至少 20 组真实标签正/负样本；跌倒含遮挡/坐下/捡物，吃药含只喝水，起身含翻身。
2. 故障注入：断网、慢/失败平台、摄像头冻结、模型损坏、SQLite 只读、Mac 重启/睡眠、HA 离线。
3. classic 与 VLA 分别连续运行 72 小时，记录 CPU、RSS、帧年龄、事件延迟、通知成功率。
4. 真实双向链路：老人发消息、家人问状态、家人留言与回复、紧急告警回执。
5. 最终 go/no-go 报告；未通过项明确禁止用于无人值守，而不是用“基本正常”放行。
